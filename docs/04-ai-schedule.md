# 《小城烟火》AI 原生开发排程

**版本**：V1.0  
**日期**：2026 年 11 月 1 日  
**执行方式**：24/7 连续执行，6 个 AI Sprint × 48h + Bootstrap 24h + G1 Buffer 24h = **336 小时 / 14 天**  
**原则**：人类只定义目标、约束、验收和 Gate；AI Orchestrator 动态拆解任务；AI Agents 并行生成、测试、集成；人类只在关键 Gate 做品味、合规、平台、用户和最终决策。

---

## 0. 结论

- **旧的人类 6 周 / 13 人排期作废**，仅保留为“人类团队参考版”。
- 不再人工拆 100+ 条任务。人类给出 **6 个 Sprint 的 Outcome + Acceptance + Gate**，由 Orchestrator 在运行时拆成任务包。
- AI 原生目标：**14 天 / 336 小时**交付 Cocos 微信小游戏 Demo，完成 20 人测试与 G1。
- 三个瓶颈不可压缩：**人的品味判断、平台账号/审核、真实用户测试**。
- AI 不是“按 8 小时上班”，而是 **24/7 连续循环 + 4 小时构建 + 12 小时人类 digest + 48 小时 Gate**。
- 浏览器可玩原型（`demo/`）作为视觉/交互参照；Cocos 版复用配置、流程和测试脚本，不复用 JS 代码。

> 这不是“6 周变 3 天”的口号。它是把“人天排期”换成“任务包 + 自动验收 + 并行 Agent + 人类 Gate”的执行系统。

### 0.1 时间弹性

| 情景 | 天数 | 条件 |
|---|---:|---|
| 激进 | 10–12 天 | 风格包预批、Gate <1h、测试 AppID/用户就绪、艺术返工少 |
| 基准 | 14 天 | 本排程假设 |
| 保守 | 16–18 天 | 美术返工、平台账号/审核延迟、20 人招募不足 |
| 停线 | — | 版权/合规/安全 P0，立即停止等人类处理 |

## 1. 为什么不是“人工排期 + AI 加速”

| 维度 | 人类 6 周排期 | AI 原生 14 天 |
|---|---|---|
| 任务分解 | 人把工作拆成 121 条任务 | Orchestrator 按 Outcome 动态拆成任务包 |
| 估算单位 | 人天（PD） | 任务包 + 验收测试 + 循环轮次 |
| 并行方式 | 13 人，8 小时/天 | 10–12 个 Agent，24/7 |
| 验证方式 | 人工 QA + 评审 | 自动测试 + Critic Agent + 人类 Gate |
| 主要瓶颈 | 人力 | 人的品味、平台账号、真实用户 |
| 成本结构 | 人力工资 | 算力/API + 少量人类 Gate |
| 风险 | 排期延误 | 幻觉、集成冲突、风格漂移、版权 |

**核心变化**：

1. 人类不再写“第 1 天谁做什么”，而是写“这个 Sprint 必须产出什么、怎么自动验收、什么情况下必须停下来找人”。
2. AI 不再被当作“更快的人”，而是被当作“可并行、可回滚、可自动验证的生产单元”。
3. 人类时间从“开发”转移到“Gate”：定方向、看品味、处理合规、跑真实用户。

## 2. AI 开发系统

### 2.1 Agent 角色

| Agent | 职责 | 自主级别 | 主要输出 |
|---|---|---|---|
| Orchestrator | 维护目标图、拆任务、调度、解决冲突、升级 | L3 | 任务图、Sprint 报告、风险清单 |
| Product/Design | 把 GDD 转成机器可读规格、配置、验收测试 | L2 | specs、config、UX flow |
| Architecture | 仓库结构、模块接口、编码规范、依赖管理 | L3 | 架构文档、接口契约、CI |
| Client A | Cocos 框架、二合、改造、性能 | L3 | 客户端核心代码 |
| Client B | 订单、UI、剧情、分享、平台 UI | L3 | 客户端功能代码 |
| Client C | 经济、存档、埋点、支付/广告 SDK | L3 | 客户端/平台代码 |
| Art Director | 风格包、参考图、风格一致性 Critic | L2 | style pack、art bible |
| Art Generator | 物品、店铺、角色、UI、分享卡 | L2 | PNG/SVG/图集 |
| Audio | 音乐、音效、配音、混音 | L2 | WAV/MP3/OGG |
| Backend/Data | 服务、配置、埋点、看板 | L3 | API、dashboard |
| QA | 测试生成、自动化、设备矩阵、Bug 报告 | L3 | test suite、bug list |
| Build/Release | CI/CD、Cocos/微信构建、包体、性能 | L3 | 构建产物、性能报告 |
| Critic/Reviewer | 代码/设计/安全/合规审查 | L3 | review comments、block list |
| Human Gate | 品味、范围、合规、账号、用户、最终决策 | L0 | Go/Iterate/Kill |

### 2.2 协作拓扑

```
Human Gate (L0)
      ↕
Orchestrator (L3)
  ├─ Product/Design → specs/config/acceptance
  ├─ Architecture → repo/interfaces/CI
  ├─ Client Pod A/B/C → code
  ├─ Art Pod → assets
  ├─ Audio Pod → audio
  ├─ Backend/Data → service/analytics
  ├─ QA Pod → tests/bugs
  ├─ Build/Release → builds/perf
  └─ Critic → review/security/compliance
```

- 所有 Agent 通过 **repo + task graph + artifact store** 协作。
- 每个任务在独立 worktree/branch 执行，禁止直接提交 main。
- 合并必须通过 CI + Critic + 自动验收。
- Orchestrator 每 4 小时重新规划一次；每 12 小时向人类发 digest。

### 2.3 任务包协议（AI Task Packet）

人类不写“第 1 天做什么”，而是让 Orchestrator 生成这种任务包：

```yaml
id: C1-MERGE-01
sprint: C1
goal: 实现 Cocos 7x7 二合棋盘、点选/拖拽、6 级合成、2 个产出器
owner: client-a
reviewer: critic
inputs:
  - specs/merge.md
  - specs/items.json
  - assets/style-pack/v1
constraints:
  - Cocos Creator 3.8 / TypeScript
  - 中端安卓 60fps
  - 主包 < 4MB
acceptance:
  - unit: 两个同级物品合成下一级
  - unit: 最高级不可继续合成
  - ui: 截图对比 baseline，差异 < 2%
  - build: 微信开发者工具构建通过
  - perf: 100 次合成无卡顿
outputs:
  - src/game/merge/**
  - tests/merge.spec.ts
  - artifacts/build/wechat/C1
deadline: 48h
rollback: git revert branch
```

**规则**：

- 没有可执行验收标准的任务，不允许进入执行。
- 没有明确输入/输出的任务，Orchestrator 必须打回。
- 验收失败 2 次 → 换策略；失败 3 次 → 人类 Gate。

### 2.4 自主级别

| 级别 | 含义 | 适用 |
|---|---|---|
| L0 | 人类决策 | G1、版号、合同、平台账号、最终品味 |
| L1 | AI 建议，人类执行 | 支付签约、法律文件、版权 |
| L2 | AI 执行，人类批准 | 美术风格、剧情方向、商业化 |
| L3 | AI 执行 + 自动验收 + 抽检 | 代码、测试、构建、数据 |
| L4 | 全自动 + 回滚 | 低风险重复任务（图标变体、埋点补全） |

### 2.5 质量护栏

| 维度 | 自动检查 | 人类 Gate |
|---|---|---|
| 代码 | tsc、lint、unit、integration、build | 架构/关键模块抽检 |
| UI | 截图对比、分辨率适配、点击热区 | 前 8 分钟体验 |
| 美术 | 风格参考包、一致性评分、尺寸/命名 | 风格 Gate |
| 剧情 | 敏感词、长度、可跳过、无死循环 | 情感/价值观 |
| 数据 | 事件 schema、漏斗对账、无 PII | G1 指标解释 |
| 平台 | 包体、构建、真机、支付/广告沙盒 | 提审/合规 |
| 安全 | 密钥、依赖漏洞、越权、注入 | 高危问题 |

### 2.6 失败升级

| 情况 | 动作 |
|---|---|
| Agent 连续 2 轮验收失败 | Orchestrator 换 prompt/拆小任务 |
| 连续 3 轮失败 | 升级人类 Gate |
| 合并冲突 | Architecture Agent 解决；未解决升级 |
| 美术被 Critic 判定风格漂移 | 用 style pack 重生成；3 次后人类 |
| 性能/包体回退 | Build Gate 阻止合并 |
| 测试 flaky | QA 隔离，不允许合并 |
| 安全/合规问题 | 立即停止，人类处理 |

## 3. 6 个 AI Sprint 总览

| Sprint | 时间（小时） | 自然日 | Outcome | 并行 Agent | 人类 Gate |
|---|---:|---|---|---:|---|
| C0 Bootstrap | 0–24h | Day 0–1 | 仓库/CI/空构建/规格/风格包 | 5 | G1：方向/风格/任务图 |
| C1 Core Merge | 24–72h | Day 1–3 | 二合核心 + 30 物品 + HUD | 8 | G2：手感 |
| C2 Orders | 72–120h | Day 3–5 | 订单/经济/首章 + 15 分钟循环 | 9 | G3：节奏 |
| C3 Renovation | 120–168h | Day 5–7 | 改造/剧情/分享 + 25 分钟 | 10 | G4：品味 |
| C4 Full Flow | 168–216h | Day 7–9 | 30 分钟全流程 + 平台骨架 + RC1 | 10 | G5：完整度 |
| C5 QA/RC | 216–264h | Day 9–11 | 性能/埋点/RC2 + 5–8 人内测 | 8 | G6：可测性 |
| C6 User Test | 264–312h | Day 11–13 | 8–12 人测试 + 修复 + RC3 | 6 | G7：是否进 20 人 |
| G1 Buffer | 312–336h | Day 13–14 | 20 人测试 + G1 报告 | 4 | G8：Go/Iterate/Kill |

> 每个 Sprint 48h 连续执行；人类 Gate 30–60 分钟；Gate 失败则回滚/迭代 12–24h，整体顺延。

## 4. 每个 Sprint 的 Outcome 与验收

### 4.1 C0 Bootstrap（0–24h）

**Outcome**：

- 仓库、分支、CI、Cocos 空工程、微信开发者工具构建通过。
- GDD/需求文档转成机器可读 specs + 验收测试。
- 风格包（20 张参考图 + prompt library + art bible）。
- 30 人用户测试 waitlist。
- Orchestrator 任务图 v1。

**Agent Pods**：

- Orchestrator：目标图、Agent 名单、分支策略。
- Architecture：Cocos 工程、模块边界、配置 schema、CI。
- Product：specs/config/acceptance tests。
- Art Director：style pack、art bible。
- Build：空构建到微信开发者工具。
- QA：测试 harness、截图 baseline。

**自动验收**：

- [ ] `wechat build` 通过，主包 <4MB。
- [ ] specs 覆盖 30 物品/12 订单/9 改造/6 剧情。
- [ ] 每个功能有对应验收测试。
- [ ] 风格包通过 Art Critic 一致性检查。

**人类 Gate G1（24h）**：

- 看风格包、任务图、Sprint 计划。
- 决定：继续 / 换风格 / 缩范围。
- 通过后进入 C1。

---

### 4.2 C1 Core Merge（24–72h）

**Outcome**：

- 7×7 二合棋盘、点选/拖拽、6 级合成。
- 2 个产出器、30 个物品、基础 HUD。
- 合成/产出 VFX + 音效。
- 微信构建可玩。

**Agent Pods**：

- Client A：框架、场景、配置、存档。
- Client B：棋盘、合成、产出器、动画。
- Client C：HUD、体力、输入。
- Art：30 物品图标、店铺基础、UI kit。
- Audio：合成/UI SFX。
- QA：unit + 10 分钟自动通关。
- Build：每 4h 构建。

**自动验收**：

- [ ] 6 级链条全部可合成。
- [ ] 最高级不可继续合成。
- [ ] 30 次产出无异常/无卡死。
- [ ] 中端安卓 ≥50fps。
- [ ] 微信构建通过，主包 <4MB。

**人类 Gate G2（72h）**：

- 亲手玩 5 分钟，判断“合成手感”。
- 通过：进入 C2；不通过：重做动画/音效/掉落。

---

### 4.3 C2 Orders（72–120h）

**Outcome**：

- 12 个订单、3 个槽位、逐步解锁。
- 铜钱/体力/钻石/零件经济。
- 仓库/特殊物品/图鉴。
- 教学 1–4 步。
- 15 分钟循环：产出 → 合成 → 订单 → 改造前置。

**Agent Pods**：

- Client A：订单系统、刷新、奖励。
- Client B：仓库、特殊物品、教学。
- Client C：经济、体力、存档、配置。
- Product：12 单/30 物品/教学脚本。
- Art：店铺内景、角色草图、UI kit v2。
- Audio：主音乐、6 个音效。
- QA：订单/经济测试、15 分钟自动通关。

**自动验收**：

- [ ] 12 单全部可交付，奖励正确。
- [ ] 3 个槽位逐步解锁。
- [ ] 2 单后食材篮解锁。
- [ ] 5–7 分钟可攒够 300 铜钱。
- [ ] 体力/货币无负数、无溢出。

**人类 Gate G3（120h）**：

- 玩到第一次改造前，判断节奏是否“太快/太慢/太肝”。
- 通过：进入 C3；不通过：调订单/掉落/体力。

---

### 4.4 C3 Renovation（120–168h）

**Outcome**：

- 3 个改造区域 × 3 个方案。
- 前后对比滑块 + 3 秒运镜。
- 分享卡生成/保存。
- 6 节点剧情、对话/打字机/队列/跳过。
- 25 分钟流程。

**Agent Pods**：

- Client A：改造系统、费用、状态。
- Client B：前后对比、分享卡。
- Client C：剧情系统、P3–P6、教学第 5 步。
- Art：9 改造预览、5 角色 + 15 表情、4 格序章。
- Animation：运镜、Spine、VFX。
- Audio：改造音乐、外婆配音。
- QA：9 方案/6 节点/分享卡截图。

**自动验收**：

- [ ] 3×3 方案全部可选/可预览。
- [ ] 前后对比拖动流畅，分享卡 2s 内生成。
- [ ] 6 节点可触发、可跳过、不重复。
- [ ] 教学 1–5 步完整。
- [ ] 改造后视觉差异明显。

**人类 Gate G4（168h）**：

- 看第一次门头改造的前后对比，判断“有没有哇”。
- 通过：进入 C4；不通过：重做运镜/美术/音效。

---

### 4.5 C4 Full Flow（168–216h）

**Outcome**：

- 序章 → 12 单 → 3 改造 → 6 剧情 → 结局 → 问卷。
- 首充/广告/背包/设置/分享。
- 微信登录/存档/支付沙盒/激励视频测试位。
- 全量埋点 + 数据看板。
- RC1。

**Agent Pods**：

- Client A：结局/问卷/全流程串联。
- Client B：首充/广告/背包/设置/UI polish。
- Client C：微信 SDK/存档/支付/广告/埋点。
- Backend：部署/配置/看板。
- Art：终稿/Logo/分享卡模板。
- Audio：混音/压缩。
- QA：30 分钟自动 + 人工通关。

**自动验收**：

- [ ] 30 分钟核心路径可完整走通。
- [ ] 首充/广告/分享/问卷可用。
- [ ] 支付沙盒/激励视频测试位回调正确。
- [ ] 埋点 100% 覆盖，看板可查。
- [ ] 无 P0，崩溃 <1%。

**人类 Gate G5（216h）**：

- 完整玩一遍，判断“像一个游戏吗”。
- 通过：进入 C5；不通过：砍功能/补体验。

---

### 4.6 C5 QA/RC（216–264h）

**Outcome**：

- 包体/性能/适配达标。
- 6 台设备矩阵通过。
- 5–8 人内部测试。
- RC2。

**Agent Pods**：

- Build：包体/分包/性能/双端构建。
- QA：回归/崩溃/边界/设备矩阵。
- Client：P0/P1 修复。
- Data：埋点对账/漏斗。
- Art：压缩/适配。

**自动验收**：

- [ ] 主包 <4MB，总包 <30MB（抖音 <20MB）。
- [ ] 中端安卓 ≥50fps，崩溃 <1%。
- [ ] 6 台设备通过。
- [ ] 埋点与后台一致。
- [ ] 5–8 人内测无 P0。

**人类 Gate G6（264h）**：

- 看 RC2 稳定性/数据，决定是否进 20 人测试。
- 通过：进入 C6；不通过：修 12–24h。

---

### 4.7 C6 User Test（264–312h）

**Outcome**：

- 8–12 名目标用户测试。
- 录屏/访谈/问卷/埋点。
- P0/P1 修复。
- RC3。

**Agent Pods**：

- Human/Ops：招募/主持/访谈。
- QA/Data：观察/日志/数据。
- Client：修复。
- Product：教学/经济微调。
- Art：修图/修音。

**验收**：

- [ ] 8–12 人完成。
- [ ] P0=0，P1≤3。
- [ ] 关键指标有方向性结论。
- [ ] RC3 稳定。

**人类 Gate G7（312h）**：

- 决定是否进 20 人测试；如不达标，先修 12–24h。

---

### 4.8 G1 Buffer（312–336h）

**Outcome**：

- 20 人测试。
- G1 报告。
- Go / Iterate / Kill。

> 20 人测试可在 C6 后半段并行启动；G1 Buffer 用于补测、数据汇总和报告，而不是从零开始招募。

**Agent Pods**：

- Human/Ops：20 人测试。
- Data：分析。
- Product/Orchestrator：报告。
- Human Gate：最终决策。

**验收**：

- [ ] 20 人完成。
- [ ] G1 指标表完整。
- [ ] 报告/问题清单/决议。
- [ ] 下一阶段计划。

**人类 Gate G8（336h）**：

- Go / Iterate / Kill。

## 5. 48 小时循环节奏

每个 AI Sprint 按同一节奏跑：

| 时间 | 动作 | 负责 |
|---|---|---|
| 0–4h | 重新规划/拆任务/分配 | Orchestrator |
| 4–16h | 生成 v1（代码/美术/音频） | Agents |
| 16–20h | 自动测试/截图对比/构建 | QA/Build |
| 20–24h | Critic 审查/修复/合并 | Critic/Agents |
| 24–36h | 生成 v2/内容补全 | Agents |
| 36–40h | 集成/冲突解决 | Architecture |
| 40–44h | 回归/性能/包体 | QA/Build |
| 44–48h | 构建/录屏/Gate 材料 | Orchestrator |

**固定节拍**：

- 每 4 小时构建一次。
- 每 12 小时人类 digest（15 分钟，看 3 个指标/3 个风险）。
- 每 48 小时人类 Gate（30–60 分钟）。
- 任何 P0/安全/合规问题立即停线。

| G6 | 264h | 可测性 | 制作人/QA | 修 12–24h |
| G7 | 312h | 是否进 20 人 | 制作人 | 先修再测 |
| G8 | 336h | Go/Iterate/Kill | 制作人/投资人 | 转 B 计划 |

> 人类 Gate 总时长约 4–8 小时，不是“参与开发”，而是“做 AI 做不了的判断”。

## 8. AI 原生风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 幻觉 API | Cocos/微信 API 不存在或版本不对 | 官方文档 RAG + 版本锁定 + 编译验证 |
| 上下文漂移 | 越做越偏离 GDD | 每 4h 重新读 specs；Critic 对照验收 |
| 集成冲突 | 多 Agent 改同一模块 | 接口契约先行；worktree；Architecture 仲裁 |
| 风格漂移 | 图标/角色不像同一套 | style pack + 一致性评分 + 人类 Gate |
| 版权风险 | 生成图疑似某 IP/画师 | 禁用品牌/画师名；人工法务抽检 |
| 安全 | 密钥/隐私进 prompt | 密钥 vault；PII 脱敏；安全扫描 |
| 测试盲区 | 自动测试过、体验差 | 人类 Gate + 真实用户 |
| 平台 | 账号/审核/支付签约 | 人类提前准备；沙盒兜底 |
| 用户招募 | 20 人不到位 | Day 0 启动 30 人 waitlist |
| 过度自信 | AI 说“完成”但不可玩 | 以构建/截图/真机为准，不以文字为准 |

## 9. AI 不能做什么

以下必须由人类完成，AI 只能辅助：

1. 注册公司/账号、版号/软著/ICP、合同、支付签约。
2. 平台身份认证、提审、法务/版权确认。
3. 真实用户的招募、访谈、共情判断。
4. 最终品味判断：这款游戏“好不好玩/暖不暖”。
5. 最终责任：Go/Iterate/Kill、预算、对外承诺。
6. AI 生成素材的版权/合规审查。

> “全用 AI 开发” ≠ “全用 AI 负责”。AI 负责生产与验证，人负责方向与责任。

```text
你是《小城烟火》的 Orchestrator。目标：在 48h 内交付 [Sprint Outcome]。
```
